Browse Aisles — Complete Feature Build
What & Why
Build the full Browse Aisles feature for the Parts ID warehouse mobile app (Expo / React Native). This is a core offline-capable inventory navigation tool that lets warehouse workers "walk" the warehouse digitally by drilling through a hierarchy of Aisle → Section → Shelf → Parts without any network connectivity. It is sourced entirely from a locally cached Fuse.js inventory snapshot and integrates into both the Search tab and the Map tab.

Done looks like
lib/aisleHierarchy.ts exists and exports buildAisleHierarchy, parseBin, and all associated types
components/BrowseByAisle.tsx exists and renders the full four-level drill-down overlay
components/AisleSummarySheet.tsx exists and renders the long-press modal on the Map tab
The Search tab (app/(tabs)/index.tsx) mounts the overlay when aisleBrowseOpen is true and shows the "Browse by Aisle" entry-point button when no search results are showing
The Map tab (app/(tabs)/map.tsx) launches the overlay when a zone is tapped and shows AisleSummarySheet on long-press
Both ShelfView (single-shelf diagram) and SectionShelfView (all shelves in a section stacked) are implemented inside BrowseByAisle.tsx
The SectionNavBar Prev/Next bar and both swipe hooks (useSectionSwipe, useCardItemSwipe) are fully implemented
Android hardware back button is intercepted and pops the correct level
All styles match the dark industrial amber theme (constants/colors.ts): Inter font family, amber primary #f59e0b, dark background #0d1117, card #161b22, border #30363d, muted foreground #9ca3af, monospaced fonts for bin labels
The "Unsorted" bucket renders parts with malformed bin strings at the bottom of the aisle list
Out of scope
Any changes to the API server, database schema, or OpenAPI spec
The taxonomy/category Browse mode (BrowseTaxonomy.tsx) — that is a separate component
The WarehouseMapView SVG rendering itself — only the overlay wiring on the Map tab
Admin keyword editing flow — only pass-through of the existing onEditKeywords prop
Steps
1. Build lib/aisleHierarchy.ts — pure data layer
Create the file with no React Native imports so it is unit-testable in a plain Node/Jest environment.

Types to export:

ParsedBin { raw, aisle, section, shelfHundreds, position }
PartOnShelf { item: InventoryItem, bin: string, position: number }
ShelfNode { shelfHundreds: number, label: string, partCount: number, parts: PartOnShelf[] }
SectionNode { section: string, label: string, partCount: number, shelves: ShelfNode[] }
AisleNode { aisle: string, label: string, partCount: number, sections: SectionNode[] }
UnsortedPart { item: InventoryItem, malformedBins: string[], hasValidPlacement: boolean }
UnsortedNode { label: 'Unsorted', partCount: number, parts: UnsortedPart[] }
AisleHierarchy { aisles: AisleNode[], unsorted: UnsortedNode | null }
parseBin(raw: string): ParsedBin | null

Regex pattern: /^(\d{2})-(\d{2})-(\d{3})$/
Trims input. Returns null on mismatch.
shelfHundreds = parseInt(shp[0]) * 100 (hundreds digit × 100)
position = parseInt(shp.slice(1)) (last two digits, left-to-right)
buildAisleHierarchy(items: readonly InventoryItem[]): AisleHierarchy

Iterates every item's binLocations array. Items with no bins are skipped.
For each bin: if it parses, insert into a nested Map<aisle, Map<section, Map<shelfHundreds, PartOnShelf[]>>>. If it does not parse and the raw string is non-empty, add to malformedBins.
Any item with at least one malformed bin goes into unsortedItems (a Map<itemId, UnsortedPart>), with hasValidPlacement = true when it also has at least one valid bin.
Parts within each shelf are sorted position ASC, ties broken by item.id ASC.
Shelves within each section are sorted shelfHundreds DESC.
Sections within each aisle are sorted numerically ASC.
Aisles are sorted numerically ASC.
Distinct-part counts at every level use a Set<number> of item.id values — a part with two bins in the same aisle is counted once at the aisle level.
Labels: Aisle ${aisle}, Section ${section}, Shelf ${shelfHundreds} (e.g. Shelf 900).
unsorted is null when unsortedItems is empty.
2. Build components/BrowseByAisle.tsx — the overlay component
Props interface:

inventory: InventoryItem[]
cacheReady: boolean
onClose: () => void
fontScale: number
onEditKeywords?: (item: InventoryItem) => void
shelfViewEnabled?: boolean        // default false
initialAisle?: string             // e.g. "13" — auto-drills on mount
sectionParity?: 'odd' | 'even' | 'all'   // default 'all'
sectionNumbers?: readonly string[]       // takes precedence over sectionParity

Internal types:

type Level = 'aisles' | 'sections' | 'shelves' | 'parts'
interface CrumbState { aisle: AisleNode | null; section: SectionNode | null; shelf: ShelfNode | null }

State & refs:

crumbs: CrumbState — drives the current level
baseHierarchy — memoized from buildAisleHierarchy(inventory)
sectionAllowKey — sorted join of sectionNumbers used as a memo dep and idempotency key
hierarchy — derived view that applies the section filter (explicit list beats parity)
drilledKeyRef — ref that tracks the last ${sectionAllowKey}::${sectionParity}::${initialAisle} key drilled so the auto-drill useEffect only fires once per unique context
sectionsFlatListRef / sectionsScrollOffsetRef — scroll-position restoration for the sections FlatList when returning from a deeper level
Level derivation:

crumbs.shelf  → 'parts'
crumbs.section → 'shelves'
crumbs.aisle   → 'sections'
otherwise      → 'aisles'

Navigation:

goBack() — pops one crumb level; memoized with useCallback
goHome() — resets all crumbs to null
goToPrevSection() / goToNextSection() — walk the sibling sections within crumbs.aisle.sections
Android back handler (useEffect, platform guard Platform.OS !== 'android'):

Re-registers whenever level changes
At 'aisles' → calls onClose(); deeper levels → calls goBack()
Always returns true to consume the event
Empty-state guard: When inventory.length === 0, render Header + an emptyCard with:

Title: cacheReady ? 'No inventory loaded' : 'Inventory not synced yet'
Hint text explaining offline-first behaviour when not yet synced
Main render — four conditional blocks:

level === 'aisles' → FlatList of DrillRow for each aisle + a ListFooterComponent for the Unsorted bucket (renders a synthetic shelf/section/aisle so the parts level can display the flat unsorted list)
level === 'sections' → FlatList ref'd by sectionsFlatListRef, records scroll offset, restores it on re-entry
level === 'shelves' → either SectionShelfView (when warehouseShelfView from settings.shelfViewEnabled) or a simple FlatList of DrillRow for each shelf
level === 'parts' → either ShelfView (when shelfViewEnabled prop) or FlatList of ResultCard via a synthetic SearchResult with confidence: 1 and matchReason set to the breadcrumb path string
ResultCard usage at parts level:

result = {
  item: p.item,
  confidence: 1,
  matchReason: `On ${aisle.label} › ${section.label} › ${shelf.label}`,
  seriesLabel: undefined,
  variants: [],
}

Pass highlightBin={p.bin}, showRank={false}.

3. Implement the two swipe hooks inside BrowseByAisle.tsx
useSectionSwipe({ onSwipeLeft, onSwipeRight }) Uses PanResponder. The responder is created once via useRef and the callbacks are stored in refs (updated every render) to avoid stale closures.

onStartShouldSetPanResponder: () => false
onStartShouldSetPanResponderCapture: () => false
onMoveShouldSetPanResponder: (_, gs) => Math.abs(gs.dx) > 10 && Math.abs(gs.dx) > Math.abs(gs.dy) * 2.5
onMoveShouldSetPanResponderCapture: () => false
onPanResponderRelease: threshold is 75 on iOS, 60 on Android; dx < 0 → left callback; dx > 0 → right callback
useCardItemSwipe({ onSwipeLeft, onSwipeRight }) Same pattern but onMoveShouldSetPanResponder returns false on non-iOS platforms (iOS-only). Release threshold is 40. Must be instantiated BEFORE useSectionSwipe in every consumer so its PanResponder occupies a lower index in the capture array.

4. Implement ShelfView (parts level — shelf diagram)
Renders a horizontal ScrollView of tappable bin slots above a detail card area.

Constants:

BIN_SLOT_W = 84
BIN_SLOT_H = 76
GAP_BASE = 8       // minimum px gap between slots
GAP_PER_POS = 7    // additional px per position unit of separation

State: selectedIdx: number | null

Section-change reset: useEffect keyed on crumbs.section?.label — scrolls to x=0, y=0 and clears selectedIdx.

Slot rendering:

Gap before slot i: i === 0 ? 0 : GAP_BASE + Math.max(0, (p.position - prevPos - 1) * GAP_PER_POS)
Selected slot: backgroundColor: colors.primary, borderColor: colors.primary
Unselected slot: backgroundColor: colors.card, borderColor: colors.border
Slot content (top-to-bottom): position label (p.bin.split('-').pop()), catalog/description, sub-label (breaker amp/pole from parseBreakerCatalog or vendor)
Position label color: always #000000 (hard-coded for contrast on amber)
Name color: isSelected ? colors.primaryForeground : colors.foreground
Vendor color: isSelected ? colors.primaryForeground + 'aa' : colors.mutedForeground
accessibilityRole="button", accessibilityLabel={Bin ${p.bin}: ${catalog ?? description ?? 'part'}}, accessibilityState={{ selected: isSelected }}
Below the slots row: a physical shelf rail (height: 8, borderRadius: 4, borderWidth: 1, backgroundColor: colors.muted, borderColor: colors.border)
Below the rail: a location label ${locationLabel} · ${parts.length} part(s) in fontSize: 11, Inter_400Regular, color: colors.mutedForeground
Detail area (below diagram):

When slot selected: FlatList with a single ResultCard entry (initiallyExpanded, showConfidence={false}, highlightBin, fontScale), paddingBottom: 140
When nothing selected: a centered hint with Feather "mouse-pointer" icon + "Tap a bin above to see part details"
Swipe handlers: useCardItemSwipe (created first), then useSectionSwipe. Apply swipeHandlers to the outer View with flex: 1. Apply cardSwipeHandlers to the detail View.

SectionNavBar rendered at the top (see step 6).

5. Implement SectionShelfView (shelves level — all shelves stacked)
Stacks multiple ShelfView-style horizontal scroll rows into a vertical ScrollView.

State: selected: { shelfIdx: number; partIdx: number } | null

Shelf ordering: Reverse section.shelves before rendering so the lowest shelfHundreds appears at the top (mirrors looking straight at the front of a shelf unit).

Between-shelf separator: <View style={[sectionStyles.shelfPlank, { backgroundColor: colors.foreground }]} /> — height: 2. Shown shelfIdx > 0. Also shown after the last shelf when shelf.partCount > 3.

Shelf label: ${shelf.label} · ${shelf.partCount} part(s) in fontSize: 13, Inter_600SemiBold, color: colors.foreground, paddingHorizontal: 16.

Each shelf gets its own horizontal ScrollView (no ref) using the same slot rendering as ShelfView. Selection key is { shelfIdx, partIdx }.

Detail card: Rendered inside the same outer ScrollView, after all shelf rows. ResultCard with key={${item.id}-${bin}} to force remount on selection change, initiallyExpanded, showConfidence={false}.

Hint when nothing selected: Same centered "Tap a bin above" hint with minHeight: 80.

Swipe handlers: Same pattern — useCardItemSwipe first, then useSectionSwipe.

SectionNavBar at top.

7. Build components/AisleSummarySheet.tsx — Map long-press modal
Props:

zone: WarehouseZone | null
inventory: InventoryItem[]
onClose: () => void
onBrowse: (zone: WarehouseZone) => void

summarise(zone, inventory) (pure function, no imports from React):

Uses the same /^(\d{2})-(\d{2})-(\d{3})$/ regex inline
Filters items to those with at least one bin in zone.aisleId
Respects zone.sectionNumbers (explicit allow-list) → zone.sectionParity ('odd'/'even') → no filter
Counts distinct item.id → skuCount, distinct section strings → sectionCount
Tallies aiKeywords (first 3 per item), case-insensitive → top 3 by count → title-cases them → topCategories: { label, count }[]

Guard: if (!zone || !summary) return null

9. Wire Browse Aisles into the Map tab (app/(tabs)/map.tsx)
State:

drilldown: WarehouseZone | null — set when a zone is tapped; cleared on BrowseByAisle close
summaryZone: WarehouseZone | null — set on long-press; cleared on sheet close
handleBrowseFromSheet(zone: WarehouseZone): sets drilldown = zone and summaryZone = null.

AisleSummarySheet mount (always rendered, guards internally on zone !== null):

<AisleSummarySheet
  zone={summaryZone}
  inventory={inventory}
  onClose={() => setSummaryZone(null)}
  onBrowse={handleBrowseFromSheet}
/>

BrowseByAisle mount (conditional on drilldown !== null):

{drilldown && (
  <BrowseByAisle
    inventory={inventory}
    cacheReady={inventoryLoaded}
    onClose={() => setDrilldown(null)}
    fontScale={textFontScale}
    shelfViewEnabled={settings.shelfViewEnabled}
    initialAisle={drilldown.aisleId ?? undefined}
    sectionParity={
      drilldown.sectionParity === 'odd' || drilldown.sectionParity === 'even'
        ? drilldown.sectionParity
        : undefined
    }
    sectionNumbers={
      drilldown.sectionNumbers && drilldown.sectionNumbers.length > 0
        ? drilldown.sectionNumbers
        : undefined
    }
  />
)}

The WarehouseMapView already fires a tap callback per zone — wire it so a simple tap sets drilldown and a long-press sets summaryZone.
