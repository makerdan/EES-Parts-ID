# Workspace — Parts ID

Warehouse-floor electrical-parts identification and inventory lookup, built as
a pnpm monorepo. The flagship artifact is **Parts ID**, an Expo (React Native)
app workers use to find a part in seconds — by typing, by photo, or by
walking the aisles. A small Express API backs it with hybrid semantic search,
AI enrichment, and a curated taxonomy.

## Overview

- **What it is:** an internal tool for an electrical-supply warehouse.
  Workers search for parts by description, AI-identify a part from a photo,
  walk the warehouse aisle-by-aisle, refine results with chip filters, and
  upload bulk inventory spreadsheets — all from a phone.
- **Who it's for:** warehouse staff (the mobile app) and ops (the API +
  admin endpoints for taxonomy seeding and bulk enrichment).
- **Data flow:** Postgres + Drizzle ORM is the source of truth. The mobile
  app talks to the API via a generated React Query client (Orval from an
  OpenAPI spec). Fuse.js provides an offline fallback when the network
  drops.

## Stack

- **Runtime:** Node.js 24, TypeScript 5.9, pnpm workspaces
- **Mobile:** Expo Router v6, React Native 0.81, React Native Web (preview)
- **API:** Express 5, Drizzle ORM, Postgres (pg_trgm, unaccent extensions)
- **Codegen:** Orval (OpenAPI → React Query hooks + Zod schemas)
- **AI:** OpenAI gpt-5.1 (photo ID), gpt-5-mini (enrichment), gpt-4o-mini
  (taxonomy fallback) via Replit AI Integrations proxy
- **Testing:** Jest + ts-jest (node + jsdom envs); RNTL-style component
  tests via a custom `__mocks__/react-native.js` shim

## Getting started

```bash
# Install everything
pnpm install

# Push the dev DB schema (Postgres must be available via DATABASE_URL)
pnpm --filter @workspace/db run push

# Seed dictionaries + taxonomy (one-time, from artifacts/api-server/)
cd artifacts/api-server && node --import tsx/esm --no-warnings src/seed/run.ts && cd -

# Run the API server
pnpm --filter @workspace/api-server run dev

# Run the Expo app
pnpm --filter @workspace/parts-id run dev
```

The Expo app is gated by a single password from `EXPO_PUBLIC_APP_PASSWORD`
(default `warehouse2024` if unset).

## Features

<!-- AUTO:FEATURES -->

**Search**

- **Hybrid semantic + Fuse.js search** — Server-side trigram + AI-keyword search with an offline Fuse.js fallback so workers can still look up parts when the network drops.
- **Browse by Category** — Three-level drill-down (category → subcategory → type) over the seeded EES taxonomy with a Search/Browse toggle on the main tab.
- **Browse by Aisle** — Walk the warehouse in `Aisle → Section → Shelf → Parts` order, parsed from existing bin codes (`AA-SS-SHP`). Read-only and offline-capable.
- **Result refinement** — Chip-based dim filters (manufacturer, amperage, etc.) plus a debounced 'Add keywords' input that narrows in-memory results without a server round-trip.
- **Highlighted matched keywords** — Result cards bold the tokens that caused the match so workers can see why each part was kept.

**Photo ID**

- **AI photo identification** — Snap a part, OpenAI vision returns candidate matches with confidence; tap to drill into details.

**Inventory**

- **Spreadsheet upload with resumable progress** — Chunked batch upserts with on-device progress that survives an app restart.
- **Per-item keyword editor** — Manual override of AI keywords directly from a result card.
- **Bulk AI enrichment (SSE)** — Server-streamed progress while gpt-5-mini fills missing keywords across the catalog.

**Reference**

- **Floating Reference modal + AI chat** — Quick lookup of electrical abbreviations, vendors, synonyms, misspellings, and slang; SSE chat for free-form questions.

**Shop**

- **Elliott Electric shop tab** — In-app browser pinned to the Elliott Electric Supply storefront for ordering parts.

**Platform**

- **Password gate** — Single-password login for the warehouse-floor use case (`EXPO_PUBLIC_APP_PASSWORD`).
- **Dark industrial amber theme** — Tuned for warehouse lighting and gloved hands.

Mobile component tests run in jsdom via a custom React Native shim
(`artifacts/parts-id/__mocks__/react-native.js`) — no `react-native-web`
required.

## Codegen workflow

The OpenAPI spec at `lib/api-spec/openapi.yaml` is the single source of
truth for client–server contracts. After editing the spec or any handler
schema:

```bash
pnpm --filter @workspace/api-spec run codegen
```

This regenerates React Query hooks (`@workspace/api-client-react`) and
Zod schemas (`@workspace/api-zod`) used by both the mobile app and the
API server.
